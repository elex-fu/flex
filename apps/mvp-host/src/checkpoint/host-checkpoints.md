Production checkpoint binding
=============================

`await createHostCheckpoints(options)` validates the installed 008/009 markers, checkpoint/revert columns, command dispatch columns, Recovery columns and actual Content/Timeline schemas. It performs no DDL and opens no writer. Pass the already-owned Store, owner, R11 registry/workspaces and R09 views. Their SQLite handles must be identical.

The required trusted ports are `authorizeSession(sessionId, actorId, scope)`, `runtimeState(sessionId, actorId)`, `leaseForContext(context)` and `captureStateFor(intent, dispatch, lease)`. Authorization is synchronous and rechecks current device/session scope inside commits; async guards reject. Runtime state returns an actual WorkspaceLease, generation and private native handle (explicit null is allowed). The factory reads current revision, exact active relation, actual active Timeline epoch and registered roots itself. It builds the checkpoint lease token from the real lease operationId and actual owner generation. A lease for another checkout, a moved registration, stale epoch, changed original dispatch/Turn identity or blocked restore readiness cannot create a valid preview. Read-only Diff never loads a Provider runtime.

`host.executionBinding` plugs directly into R06 `checkpoints`; its original intent/dispatch/lease checks construct captureBefore/captureAfter context under the held lease. R06 owns before-prompt ordering and terminal commit/producer-stop evidence. `host.bindWorker(worker)` synchronously registers `checkpoint_revert` before Worker startup. A generic intent can run only after R06's durable claim and dispatch marker; startup never replays an unknown external step.

`revert` is optional. Its ports are actual lease acquisition, original dispatchContextFor, proveQuiescence, synchronous same-Store projectSuccess and assertRestoreWriteReady. Optional NativeRevertDriver and verifiedNativeCapabilities supply exact versioned native evidence; absence never proves rewind. `projectSuccess` must create/backfill/activate the real R09 epoch and persist the verified private Session native handle in the same Engine transaction. The factory verifies both the actual epoch/source coverage and persisted native binding before completion. In-memory runtime pointers may update only after the transaction commits. publishCommittedEvents receives durable stage/result batches after SQL success.

When `revert` is configured, `restoreOptions.spawnHelper` is required. Its request contains trusted constant command/arguments/environment, `purpose: probe|read|mutate`, the generated operationId/stepId for mutation and the trusted registered workspace root for boundary selection. The root adapter must reload the persisted step attempt and original immutable DispatchContext, journal launch with ManagedProcessRegistry/SqliteProcessJournal before spawn, and use the verified NativeExecutionBoundary when required. No mutation JSON enters stdin until the managed runner returns. `onSpawn/onExit` are diagnostic; they do not prove tree stop. The default raw runner remains available to standalone low-level tests, and the production factory never silently selects it for revert.

`host.drain(deadlineMs)` waits for service/request promises and reports timeout. It does not prove descendant stop or release a lease. Root must also drain the original managed helper/native registries, obtain trusted tree-stop proof and retain unknown exclusion when proof is unavailable. Call `host.seal()` before closing Store on a deadline; this seals capture/revert/helper publication. Seal the root managed journals as part of the same lifecycle sequence.

`capabilitiesForSession(sessionId, actorId)` probes actual registered Git support and returns fixed support facts. Basic `checkpoint-diff-v1` covers historical Diff, read-scoped preview, stored operation reads and explicitly named workspace/recovery routes. `checkpoint-revert-v1` is advertised only when the controlled helper actually probes successfully and the injected native verifier returns conversation-rewind evidence matching the current verified Provider version and native binding. executeRevert requires that negotiated capability and reloads evidence. workspaceRestore requires the basic capability, current write permission, a verified helper and configured trusted revert ports; without a new conversation transition it remains blocked with NEW_CONVERSATION_REQUIRED. No native full-rewind readiness is inferred from filesystem restore.

Compose `host.dispatchCheckpoint(frame, context)` before legacy Dispatcher routing, after transport authorization. It returns `{handled:false}` for unrelated methods or `{handled:true,payload}`. Context supplies authenticated subjectId, protocolVersion=2, negotiated capabilities, assertAuthorized and assertSessionScope; frameBudget/responseEnvelope bound the complete application frame. Supported methods: checkpoint.getDiff/getTurnDiff/getSessionDiff/getFile/previewRevert/getPreview/executeRevert/workspaceRestore/getRevertOperation/inspectRevert/resumeVerified/rollbackToSafety. Mutating command routes require identical body/envelope commandId plus explicit confirmation. inspectRevert requires write scope because it persists short-lived recovery evidence. Other reads and preview require read scope. The factory revalidates authorization after awaited work.

Public results are strict protocol DTOs only. Internal manifests, refs, leases, private native handles and absolute roots never leave this port. Relative Git filenames are validated; inline and referenced content redact registered roots plus verified macOS canonical aliases before hashing. Errors expose a bounded code, not raw Git/native/helper messages. RESPONSE_TOO_LARGE is a recoverable RPC error.

`CheckpointClient({request,supports})` is a separate typed adapter for the existing V2 RpcClient; root/client composition owns attaching it to HostRuntime. It parses requests and strict DTO responses, verifies Session/checkpoint/plan/operation identity, requires negotiated capabilities and repeats exactly one commandId in the body and envelope. It never accepts an actor, path, ref, lease or native handle from application UI state. Existing client.ts/rpc-client.ts/outbox remain untouched.
