R16 production integration
==========================

Install `applyRevertSchema(owner.db)` with R07 recovery columns and the R14 checkpoint schema inside the owned migration009 transaction. `validateRevertSchema` and `REVERT_REQUIRED_COLUMNS` are exported for the version gate. Construction opens no writer and performs no DDL. CheckpointStore already protects both refs for every retained safety/revert pin; do not remove a blocked operation's pins.

Register `worker.registerOperation(REVERT_INTENT_KIND, intent => service.handleIntent(intent))` before Worker startup. Every accepted intent contains an immutable DispatchContext supplied by the trusted factory; its generic `flyxTurnId` is the generated operation ID. Normal Worker claim and dispatch-marker commits add two Session revisions. When a custom hook adds revisions, `verifyWorkerRevision` must verify the actual marker's transaction proof; never accept a client-reported revision or fence.

`acquire` must take the real registered checkout lease and return authoritative actor/Session facts. Changed fences require `verifyLeaseSuccession` proof from the lease manager of the exact predecessor and no intervening writer. `resolveContext` and `revalidateActorInCommit` authorize the original actor with the operation's write scope; the latter runs synchronously inside each admission/dispatch/final SQL commit. Original native binding and epoch stay unchanged until the final metadata projection. Explicit recovery can bind a new runtime/owner only after short-lived, single-use evidence proves original writers stopped.

The raw restorer uses a trusted Host Python executable (default `/usr/bin/python3`) with isolated stdlib code, stdin requests, open directory descriptors and O_NOFOLLOW. Probe it before advertising support. Windows or missing POSIX dir_fd support is explicitly unavailable. Wire `ControlledRestore.onSpawn/onExit` to R04 producer/process tracking. A dispatch marker exists before the helper starts or receives mutation input. Recovery `proveQuiescence` must reload original owner/helper facts and prove all old workspace writers stopped; a missing process handle is not proof. On a close deadline call CheckpointService.seal() and RevertService.seal() before the shared Store closes; late results retain original capturing/dispatch journals and pins without DB publication. `drain(deadlineMs)` returns false when native/helper work remains unresolved, and the lease must stay retained.

NativeRevertDriver.prepare must report an exact verified conversation-rewind capability or new-conversation capability. Its target binding is SHA256(canonical JSON `{checkpointId,nativeHandle:target.nativeHandle,phase:target.phase}`). Apply/query proof binds the persisted request token, immutable original handle and target boundary; transcript history, local ACK, timeout, or cursor absence is insufficient. Query must explicitly prove quiescence and no pending request before applied/not-applied recovery is accepted. Unsupported full revert is rejected. Explicit workspaceRestore can restore files, then remains blocked with NEW_CONVERSATION_REQUIRED until a verified new conversation/recovery transition succeeds.

`projectSuccess(db,{operation,epoch,nativeProof,sourceSequence})` must perform only synchronous SQL on the same handle. Create/validate/activate the real R09 epoch (TimelineProjector.createEpoch + TimelineBackfill.run or bounded building/backfill prepared ahead of activation), persist the verified active native metadata, and return `{epoch,nativeHandleBinding}` matching the proof. Keep prior events, receipts, epochs and bindings. Do not mutate in-memory runtime pointers before the outer transaction succeeds. R16 writes its own view boundary and clears only its exact owned recovery gate in that transaction. Async results, identity mismatch or SQL failure cannot report completion.

Accepted/resume/rollback command events publish through CommandEngine. Wire `publishCommitted` to the same canonical event publisher for durable stage/result commits; it is called after SQL succeeds. Publisher failure leaves durable events available for replay.

Public methods: accept, getOperation, inspectRecovery, resumeVerified, rollbackToSafety. RPC accepts only Session/plan/operation/evidence IDs, command IDs, expected revision and explicit confirmation; actor, paths, refs, native cursors, leases and executable paths come from trusted Host state. Strict schemas are in revert-api.ts. Reads require session:read; execution/recovery/rollback require session:write. Root owns Dispatcher/client/UI/capability activation.

Safety rollback is a separate accepted command/intent/operation. It restores only the original planned workspace paths and the independently retained safety index. Old owned temp/lock cleanup is separately journalled; foreign files and index.lock are never removed. Existing directory/file parent collisions, unsupported captures/submodules/conflicts, corrupt objects, unavailable helpers, changed roots, and filesystem races fail explicitly. No branch reset, git clean, checkout, hooks, filters, textconv, external diff or FSmonitor runs.
