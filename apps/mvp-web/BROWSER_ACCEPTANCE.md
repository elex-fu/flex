# Deterministic browser acceptance

This run uses the actual production Web bundle in Google Chrome 155.0.8059.40 through Playwright 1.61.1's explicit `chrome` channel. It uses real loopback HTTP, WebSocket, and local TLS/E2EE Relay transports with the deterministic adapter. Every run provisions its own Git workspace, Host database, identity, coordination files, token claims, and random ports. `RUN_REAL_CLAUDE=0` and `RUN_REAL_CODEX=0` remain set; no paid Provider or external push call is part of this evidence.

```sh
RUN_REAL_CLAUDE=0 RUN_REAL_CODEX=0 FLYX_E2E_BROWSER_CHANNEL=chrome FLYX_E2E_KEEP_DATA=0 pnpm --filter @flyx/mvp-web test:e2e --project=chromium --trace=on
```

Omit `FLYX_E2E_BROWSER_CHANNEL` to use Playwright's installed Chromium bundle. This optional channel selector does not install a browser or alter production Web behavior. The normal runner saves failure screenshots and traces under `e2e/.artifacts`; `--trace=on` also retains passing traces. The five entry tests save review screenshots in each test's artifact directory.

The existing 24 browser cases cover pairing/replay rejection, text/tool/approval/error/interrupt flows, Diff, repeated Turns, page closure/reload, local forget versus remote revocation, pinned identity, RPC transport routing, QR, CSP/Trusted Types, Host SIGKILL, and a 30-second offline partition. The five additional entry cases exercise durable draft reload with stable message identity and retained newer edits, a real IndexedDB write failure that prevents command sending, verified loading of a 360 KB canonical Timeline body, a large Git Diff reference, and receipt-only review of an unknown saved command without replay.

Browser inspection found that old E2E storage readers requested IndexedDB v1 despite the actual v2 store, some selectors still named removed authorization controls, and the local Host fixture had no deterministic release/shutdown proof. Fixture shutdown now interrupts and awaits every original in-process run before reporting stopped; it does not claim an OS process boundary. SIGKILL restart first uses offline Host-owner maintenance, which inspects the original process birth as exited. It never directly unlinks an owner lock. Web typed Interaction controls are gated by the actual negotiated capability; legacy approvals additionally require a fresh active Turn in `waiting_approval` and current device rights. Tool cards preserve input alongside completed output, and committed recovery restrictions remain visible while local drafts stay editable.

The pending-approval SIGKILL case exposed a real Host defect: recovery committed `turn.reconciled` as `outcome_unknown` while retaining an answerable legacy approval. The parent fix `b0a4b92` supersedes only the original Turn's approvals in the same committed batch. The browser assertions retain the supersession and empty-pending checks; they are not skipped or relaxed into a pass.

The complete final run passed all 29 cases with no retries or skips. It retained 29 traces and five explicit review screenshots. Web controller/component regressions (52 tests), Web source/test types, Host source types, and the three deterministic adapter/shutdown tests also passed. The Host base is `de38bc5` plus that accepted parent recovery fix. Catalog capability activation and explicit Session switching are still pending central production integration. Typed native questions, a physical phone, actual Provider execution, and native push delivery are not established by this deterministic desktop-browser evidence. The Relay case's narrow viewport is browser emulation.
